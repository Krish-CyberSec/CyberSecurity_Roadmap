**If websites have names like `google.com`, why do computers still need IP addresses?**

When I first started learning networking, I assumed a website's name was enough for computers to communicate.

Then I learned something interesting.

Computers don't actually understand names like **google.com** or **github.com**.

They communicate using **IP addresses**.

Think of it like ordering a package online.

Knowing someone's name isn't enough for the delivery partner to find them.

They need a complete address.

The same idea applies to computers.

Every device connected to a network needs a unique address so data knows exactly where it should be delivered.

That address is called an **IP Address**.

While learning this topic, I also came across two concepts that every beginner should understand:

• **Private IP Address** – Used for communication inside your local network (like your home or office).

• **Public IP Address** – Assigned by your Internet Service Provider (ISP) and used to communicate over the Internet.

From a cybersecurity perspective, IP addresses are much more than just numbers.

They're one of the first things security analysts examine during an investigation.

Questions like these often start with an IP address:

* Where did this login attempt come from?
* Is this IP associated with previous malicious activity?
* Is it part of our internal network or an external source?
* Should this connection be blocked?

The more I learn, the more I realize that networking isn't just about making devices communicate—it's about understanding the foundation on which almost every cyberattack and every defense is built.
