One question has been on my mind ever since I started learning cybersecurity:

**Why should a GRC analyst understand networking?**

When we think about networking, we usually associate it with roles like Ethical Hacking, SOC, Security Engineering, or Cloud Security.

So I naturally wondered:

> *"GRC professionals focus on risk, policies, compliance, and audits. Why would networking matter to them?"*

I think many beginners have the same question.

The more I learned, the more I realised that cybersecurity isn't a collection of isolated domains. Every role has a different responsibility, but they all rely on the same foundation.

That foundation is **networking**.

Networking isn't just about routers, switches, or cables. It's about understanding **how systems communicate**.

If we look at different cybersecurity roles:

🔹 **SOC Analyst** – Investigates suspicious network traffic, malware communication, and lateral movement.

🔹 **Security Engineer** – Designs secure network architectures, configures firewalls, VPNs, and network segmentation.

🔹 **Cloud Security Engineer** – Secures communication between cloud resources, virtual networks, and identities.

🔹 **GRC Analyst** – Reviews network architecture, understands how sensitive data flows across the organisation, evaluates network-related risks, and verifies that security controls align with business objectives and regulatory requirements.

No matter which domain you choose, if you don't understand how systems communicate, it becomes much harder to understand how attackers exploit that communication—or how organizations should secure it.

That realisation completely changed my perspective.

I no longer see networking as a topic only for technical roles.

I now see it as the **common language of cybersecurity**.
